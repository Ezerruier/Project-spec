# Project Spec

> 版本: v1.6.0
> 更新日期: 2026-11-17

研究与分析项目的目录、脚本、数据、日志和审查规范。用于新建项目、维护分析产出、阶段交付与整理既有工作区；主动评估多 Agent 分工、Git 提交时机和 `.gitignore` 必要性。

## 使用与按需读取

将整个技能目录交给支持 `SKILL.md` 的环境，保留 `references/` 相对位置；入口名称仍为 `project-spec`。不要求某个平台、固定 Agent 数量或专门的调度系统。

| 文件 | 何时读取 |
|---|---|
| [SKILL.md](SKILL.md) | 核心入口：触发条件、授权与保护边界、任务路由、关键决策 |
| [场景流程](references/workflows.md) | 新项目、日常维护、阶段交付及按风险自查 |
| [编写约定](references/authoring.md) | 脚本头注释、参数、路径、编码、命名与文档元信息模板 |
| [多 Agent 协作](references/collaboration.md) | 可获益的委派、依赖协调、共享写入和集成验收 |
| [Git 与忽略规则决策](references/git-decisions.md) | 提交建议、暂存保护、Git 适用性与 `.gitignore` 用户裁决 |
| [既有工作区整理](references/workspace-organization.md) | 来源/依赖盘点、精确删除授权、可回退迁移及证据边界 |
| [旧编号映射](references/legacy-mapping.md) | 旧条款号、附录一、18/22 条自查与当前章节的对应 |

生成或修改文本文件后，运行 `scripts/check_text_health.py`；涉及 `.gitignore` 时加 `--gitignore`。

单文件小修改直接完成并做相称检查；独立调查可主动并行委派。无子 Agent 工具时正常单 Agent 执行并如实说明。阶段门围绕真实依赖产出设置，自查按任务选择，不再要求每次产出执行完整 22 项清单。

## v1.6.0 变化与兼容性

- 明确宿主平台委派规则优先：主 Agent 默认自行完成、仅在用户明确要求时委派的环境，不再把“主动协作”当作自行委派授权。
- 增加稳定边界锚点 PS-B1–PS-B6 与 `references/legacy-mapping.md`；旧条款号、附录一、18/22 条自查可定位到当前章节。
- 新增 `scripts/check_text_health.py`：检查严格 UTF-8、BOM、CRLF、NUL、疑似乱码与 `.gitignore` 红线；流程中按需运行。
- 新增嵌套独立仓库与文章级冻结清单、阶段门命名与看板模板、`docs/prompts/` 提示词归档目录、状态陈述 as-of 规则。
- 兼容性：技能名、文件格式与核心保护边界不变；历史文件不批量重命名，旧引用通过映射表兼容。

## v1.5.0 变化与兼容性

- 将 v1.4.0 的 15 条规范、长模板和启动清单收敛为核心入口与场景参考，保留历史整理经验和原始数据、目录职责、可回退迁移、暂存区及验证证据保护。
- 主动判断委派收益，明确分工、真实工具限制、依赖、共享编辑、失败处理和主 Agent 最终验收；不把任务分解描述成真实调用。
- 连贯改动形成时主动说明改了什么、实际验证、提交建议及理由。提交、推送、发布分别按授权执行。
- 启动不再默认创建 `.gitignore`、初始化 Git 或首次提交。忽略规则先检查实际文件并提供具体利弊与规则方案，由用户裁决；文档示例不等于实际规则变更授权。
- 移除 `_*.py` 等泛化忽略建议，保护 `__init__.py`、正式日志和复现材料；阶段模板补齐版本、日期、修改记录，完整性检查区分筛选、聚合、拆分、连接和迁移。

这是能力增加与默认行为修正，因此采用次版本 **v1.5.0**：技能名、研究分析定位和保护边界保持，文件格式未引入不兼容接口。行为上有意收紧自动 Git 与忽略规则操作；15 条编号及 22 项全量清单不再是稳定入口，外部按编号引用需改为上表中的场景文件，旧引用可查 [legacy-mapping](references/legacy-mapping.md)。无需迁移历史文件、重写 Git 历史或自动调整现有项目。参考文件独立维护版本，新参考从 v1.0.0 起；整理参考升级为 v1.1.0。

本次验证的范围、场景推演与真实工具结果见[升级验收记录](docs/audit/upgrade-v1.5.0.md)。文档场景推演不代表跨平台真实 Agent 调用已全部测试。

从 GitHub 克隆或使用 Code → Download ZIP 后，可在仓库根运行 `python3 scripts/verify_upgrade.py .` 复查当前快照；需要 Python 3 和 Git。[验证脚本](scripts/verify_upgrade.py)与[本次实际结果](docs/audit/verification-results-v1.6.0.txt)一并保留在仓库中；v1.6.0 的验收记录见[升级验收记录](docs/audit/upgrade-v1.6.0.md)。
