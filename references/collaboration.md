> 更新日期: 2026-11-08

|---|---|---|---|

接到任务、出现新的可拆分工作或需要独立复核时读取。主 Agent 始终负责目标、依赖、结果整合和最终验收；委派不转移这些责任，也不扩大授权。本参考适用于环境实际提供的 Agent 能力，不要求特定平台、固定角色或固定 Agent 数量。

## 判断是否委派

每次接到任务及发现新的可拆工作时，主动检查以下条件，不等待用户要求调用子 Agent：

- 工作能独立并行，或独立上下文、独立复核能提高质量；
- 输入和边界已足够明确，交付物可以验收；
- 预期节省的时间或提升的质量足以覆盖沟通、协调和整合成本。

满足条件就按当前能力委派。单文件小修、紧密依赖同一上下文的修改、协调成本高于收益的任务，由主 Agent 直接完成。不要为体现协作而机械拆分每一步，也不要预设必须同时启动多少 Agent。

先识别环境真实提供的创建、传递上下文、收取结果、追踪状态等能力，以及并发、权限和上下文限制。按可用能力选择任务规模和同时执行量；使用受支持的方式交接输入。没有子 Agent 工具时，继续单 Agent 执行，并简明说明该限制及对计划的影响。内部任务分解或角色视角复核不能描述为实际子 Agent 调用。

## 明确分工后再启动

主 Agent 给每个子任务提供完成所需的上下文，至少明确：

1. 目标及必要输入：要回答的问题、已知事实、相关文件或版本、已有决定。
2. 边界及依赖：可读写范围、禁止动作、所依赖的上游结果、授权限制。
3. 交付物及验收标准：返回什么文件、结论或证据，如何判断可用于集成。

编辑任务还要指定文件或区域归属。共享工作区中，在子任务结束或明确交还前，其他 Agent 不同时修改该区域。不能假定独立会话意味着独立文件系统；先确认环境的共享方式。

简单委派可用几句话，不强制生成任务表、独立计划文档或逐次审批。轻量模板：

```text
目标：……；输入/基线：……。
范围：只读…… / 只编辑……；依赖：……；授权边界：……。
交付：……；验收：……；不要修改其他文件或执行范围外操作。
```

主 Agent 保留一份足以协调的任务状态：哪些拟议、哪些已实际启动、哪些在等待依赖、哪些已返回待验收。小任务可直接在上下文中维护，不必另建调度文档。

## 按依赖协调执行

- 独立的只读调查和审查可以并行，例如分别核对脚本读写路径、数据来源、文档引用。
- 下游依赖上游产出时，先完成并验收必要的上游结果，再启动依赖它的执行；可提前开展不依赖结果的准备工作。不要把待确认的假设当成已验证输入。
- 多个编辑任务优先划分不同文件或明确区域。确需写共享文件或资源时，按环境能力选用隔离工作区、独立分支或串行编辑；隔离后的合并仍由主 Agent 协调。共享数据、索引、生成目录等资源也要指定写入责任，不能只防代码冲突。
- 共享区域变更影响另一个任务的输入时，告知新的基线和衔接要求；必要时暂停该项或收回编辑权，避免覆盖已完成工作。

阶段门围绕真实阶段产出及下游依赖设置，见[任务流程参考](workflows.md)。不因一次委派增加新的阶段审批或审计流程。

## 收取结果与验收

子 Agent 返回实际完成内容、依据和验证结果，并明确未完成项与不确定性。可用简短格式：

```text
实际完成：……（文件/区域或结论）。
依据：……（可定位的输入、差异或证据）。
验证：……（实际执行及结果；未执行及原因）。
未完成/不确定性：……；需要主 Agent 协调：……。
```

主 Agent 不把“已完成”自动视为验收通过。先核对是否满足目标和边界，再检查影响结论的关键证据；编辑任务检查实际差异、越界修改和接口衔接。集成后按任务风险验证整体结果，例如引用是否仍有效、共享配置是否一致、上下游字段是否兼容。子任务的局部检查不能替代必要的集成验证。

子任务失败、超时或无法取得工具时，保留已获得的有效证据，明确受影响的交付物，选择缩小任务、补充验证、重分派或由主 Agent 接手。继续不受影响的工作；需要失败产出的下游任务保持等待，不掩盖缺口。

结论冲突时，对照各自输入版本、假设、检查范围及证据，针对冲突点补充验证；必要时独立复核或接手。不能以多数意见、启动先后或某个 Agent 的自信程度代替证据。尚不能解决时，报告分歧、影响及待核实项，暂缓依赖该结论的步骤。

## 授权与沟通边界

所有 Agent 遵守相同的数据读写、Git、删除、发布及环境权限限制。委派只分配已授权工作；子 Agent 发现需要越界操作时，返回具体方案和缺失授权，由主 Agent 协调。已有适用授权覆盖的常规分工直接推进，不逐次请求确认。

提交、推送、发布分别判断授权，真实 `.gitignore` 的变更仍按[Git 决策参考](git-decisions.md)由用户裁决。不得借子任务自动纳入用户原有暂存内容、删除原始材料或执行主 Agent 自身无权执行的操作。

汇报清楚区分“计划委派”“已实际调用并返回”“主 Agent 已验收/已验证”。说明实际采用的结果、关键局限及未完成项，不把计划或场景推演写成工具运行证据。
